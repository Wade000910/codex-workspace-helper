# Contributing

Thanks for considering a contribution.

## Before opening a pull request

1. Open an issue for a new feature or a behavior change so scope and security impact can be discussed.
2. Keep changes small and focused. Update the README when user-visible behavior changes.
3. Run `node --test` and the syntax checks in `package.json`.
4. Do not include credentials, local machine paths, private runtime captures, or real user/workspace data in commits or test fixtures.
5. For filesystem changes, add tests for both the allowed path and the denied boundary.

Security vulnerabilities should be reported privately as described in [SECURITY.md](SECURITY.md), not in a public issue.
